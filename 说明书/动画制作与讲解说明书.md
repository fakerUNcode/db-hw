## 一、 课题背景与理论模型形式化

### 1.1 存储引擎中枢：为什么需要缓冲池（Buffer Pool）？
在现代关系型与分布式数据库（如 PostgreSQL, MySQL, OceanBase）中，内存与物理外存（NVMe SSD / HDD）存在极其悬殊的时延差异：
- 物理内存（DRAM）访问延迟约为 $50 \sim 100\text{ ns}$；
- NVMe SSD 随机读取时延约为 $10 \sim 50\ \mu\text{s}$（慢近 1000 倍）；
- 传统机械硬盘（HDD）随机寻道时延可达 $5 \sim 10\text{ ms}$（慢近 10 万倍）。

为了突破磁盘 I/O 瓶颈，数据库在内存中开辟了一段巨大的连续地址空间，称为**缓冲池（Buffer Pool）**。缓冲池不仅缓存从磁盘读取的数据页，还兼具事务脏页汇聚、延迟批量刷盘（Delayed Flushing）与写合并（Write Merging）功能。

### 1.2 缓冲池核心组件的形式化定义
```
+--------------------------------------------------------------+
|                     Buffer Pool Manager                      |
|                                                              |
|  [ Page Table: Hash Map ] : page_id -> frame_id              |
|                                                              |
|  [ Buffer Frame Array ] : Frame 0, Frame 1, ..., Frame N-1   |
|     +-- page_id      : 物理页编号                             |
|     +-- data[PAGE_SZ]: 物理数据块 (4KB / 8KB / 16KB)         |
|     +-- pin_count    : 并发引用计数 (Pin 锁)                   |
|     +-- is_dirty     : 脏页修改标记                           |
|     +-- page_lsn     : 最新变更的 WAL 日志序列号               |
|                                                              |
|  [ Free List ] : 记录当前未被分配的空闲 Frame 队列            |
|  [ Replacer ]  : 置换策略器 (LRU / LFU / Clock)              |
+--------------------------------------------------------------+
```
置换算法的核心使命是：**在内存耗尽（Free List 为空）且发生缺页异常（Cache Miss）时，在常数时间 $O(1)$ 内挑选出一个 `pin_count == 0` 的受害者物理帧（Victim Frame）予以驱逐。**

## 二、 算法核心机制与 O(1) 数据结构

### 2.1 LRU (Least Recently Used) 算法深度解构
- **核心哲学**：**时间局部性（Temporal Locality）**。假设最近被访问的页面在未来被再次访问的概率最高。
- **底层数据结构**：**哈希表（Page Table） + 双向循环链表（Doubly Linked List）**。
  - MRU Head（链表头部）：代表最新被访问或载入的数据页；
  - LRU Tail（链表尾部）：代表最久未被访问的数据页，作为驱逐首选候选者。
- **状态转移复杂度**：
  - 读命中（Hit）：从当前链表摘除节点，插入 MRU 头部，耗时 $O(1)$；
  - 缺页淘汰（Miss & Evict）：直接弹出 LRU 尾部节点，释放 Frame 并注册新页进 MRU 头部，耗时 $O(1)$；
- **并发死穴**：读命中必须修改全局双向链表前后指针，在高并发下引发严重的全局 Latch 互斥争用。

### 2.2 LFU (Least Frequently Used) 算法深度解构
- **核心哲学**：**频次局部性（Frequency Locality）**。假设在系统生命周期中累计引用次数越多的页面，越代表核心元数据或核心索引热点。
- **打破传统最小堆 $O(\log N)$ 陷阱**：
  很多初学者使用最小堆维护频次，但堆的调整开销为 $O(\log N)$。在拥有数千万页面的海量缓冲池中，$O(\log N)$ 开销不可接受。
- **Ketan Shah et al. 工业级 O(1) LFU 结构**：
  1. **双向频次桶链表（Frequency Buckets List）**：每个频次作为一个 Bucket 节点，所有 Bucket 按频次自小到大用双向指针相连；
  2. **桶内节点双向链表（Doubly Linked Node List）**：每个 Bucket 内部挂载当前频次的所有页面节点；
  3. **全局 min_freq 指针**：维护一个整型指针，实时指向当前最小且非空的频次桶；
  4. **全常数级 $O(1)$ 转移方程**：
     - **Hit 命中**：节点频次由 $k \to k+1$。在 $O(1)$ 内从 Bucket $k$ 摘除，插入 Bucket $k+1$。若 Bucket $k$ 为空且 $k = \text{min\_freq}$，则递增 `min_freq++`；
     - **Evict 淘汰**：直接定位 `min_freq` 桶，弹出桶内尾部节点（决胜规则 Tie-breaker），耗时严格 $O(1)$。

### 3.1 正常过程（Normal Process）
- **流序列**：`P1 -> P2 -> P3 -> P4 -> P1 -> P2 -> P5 -> P1`
- **机制展现**：
  - `P1~P4` 依次发生冷缺页，填满 4 个空物理帧；
  - `P1`、`P2` 命中，LRU 移至 MRU 头部，LFU 晋升至 `Freq=2` 频次桶；
  - `P5` 产生首次驱逐，LRU 淘汰尾部 `P3`，LFU 在 `min_freq=1` 桶中按先入先出淘汰 `P3`，两者稳态命中率表现相近。

### 3.2 算法边界情形（Boundary & Corner Cases）
- **边界一：冷启动从空到满**：Free List 由饱和转为枯竭，算法由直接分配转入淘汰判断；
- **边界二：同频竞争仲裁（Tie-breaking Rule）**：当 `min_freq=1` 桶中同时存在多个页面（如 `P4` 与 `P5`），LFU 严格依据挂入桶内的时间先后次序，淘汰先入者，确保常数级与确定性；
- **边界三：循环抖动（Thrashing）**：当工作集为 $C+1$ 循环扫描时，LRU 命中率退化为 0%。

### 3.3 异常与病态反例（Pathological Anomaly Counterexamples）
- **反例一（击穿 LRU）：全表扫描缓存污染（Cache Pollution）**
  - **构造序列**：热点 `[P1, P2]` 多次访问建立核心地位 $\to$ 注入一次性扫描流 `[S1, S2, S3, S4, S5]` $\to$ 重新访问热点 `[P1, P2]`。
  - **结果**：LRU 盲信最近访问，冷数据霸占 MRU 头，高频热点被全部驱逐，后续请求全部发生未命中（命中率暴跌至 0%）；LFU 依靠历史累积的高频壁垒，冷数据仅在 `min_freq=1` 桶内自相替换，热点安然无恙！
- **反例二（击穿 LFU）：历史频次僵死与工作集漂移（Cache Sclerosis & Starvation）**
  - **构造序列**：早期爆发页 `[Ghost]` 集中读取 5 次积累虚高频次 $\to$ 业务切换至新热点集合 `[N1, N2, N3, N4, N1, N2]`。
  - **结果**：`Ghost` 未来再无访问，但凭借 `Freq=5` 成为无法被驱逐的“僵尸数据”；新活跃页因初入频次低被不断提前驱逐，发生严重饥饿；而 LRU 自然利用时间衰减驱逐 `Ghost`，实现秒级自适应收敛！
